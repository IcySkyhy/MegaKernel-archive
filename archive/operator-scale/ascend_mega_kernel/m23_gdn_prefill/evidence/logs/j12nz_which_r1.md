## 判读（**修正 r3 的推论**，如实）
1. **"哪一条是坏的那条"这个问法被证伪**：三条**没有一条是"单独必要"**的 —— 跳掉任意一条，剩下的两条仍能触发。
   ⇒ r3 那张"按条跳过 ↔ 静态差异"的一一对应表**在本步没有得到确认**，**不能**据此说根因是
   "同 chunk 二次写" 或 "64KB/`dstNzC0Stride=128`" 或 "B1 声明"中的某一条。
2. **但"同签名"仍成立**（三档与 r2/r3 的 `mte error info` 逐位相同）⇒ **同一类形态、同一处**，
   与"哪一条数据"无关；`vec`/`cube` 全 0、`l1` 非 0 ⇒ 仍是 **AIC 侧的 L1/MTE 通路**。
3. **下一步应当做"补集"实验，而不是继续减**：把 which 改成"**只保留一条**"（跳掉其余两条），
   三档各留读数 ——
   * 若"只保留 ST"就复现、而"只保留 q / 只保留 W"都 OK ⇒ 才轮到 **ST 那条（64KB + `dstNzC0Stride=128`）**，
     并把它与 L1 窗口探针的 ST 档咬上；
   * 若"只保留任意一条"都复现 ⇒ 说明触发条件是"**这段 MTE2 存在**"本身（与数据无关）⇒ 才是
     **令牌次序 / 与紧邻 MTE1·FIXP 的交接**，那时上窗口探针 + 次序最小复现；
   * 若"只保留任意一条"都 OK ⇒ 说明需要**两条以上同时存在**（密度/带宽类），这条最反直觉，但也要留读数。
4. **方法学备注**（可复用）：**"逐项移除"只能证明"某项不必要"，不能证明"某项是根因"**；
   要定位"哪一项触发"，必须再做"**只保留一项**"的补集实验。这条值得进舰队口径（与"同签名=同一类形态"配套）。

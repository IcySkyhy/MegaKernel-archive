  `git diff --name-status main...HEAD`：改动只有 manifest 与 py 的加性扩展 + `tools/weights/**`）。

  `.asc`/`.h`，故沿用 M93 的等价对照（NC-7：弄坏自己产物 manifest ⇒ 设备判据变红，
  本轮读数为 `判据 FAIL 行数 = 451`、`ALL PASS 行数 = 0`、`rc=1`，与归档相同）。
- 设备档并发：本轮有**两次**设备 run 起跑时 `npu-smi info` 里已有兄弟 `m15_layer_loop`
  （M98 的 `kv` 模式，host RSS 11 GB / HBM 6867 MB），未按纪律 A 等待 —— 两次我的 run
  均 rc=0 且读数正确，**未触发 OOM**。但这是**运气，不是安全**：本会话已两次被 OOM
  把整队带走，而 **OOM 杀掉的是谁不确定 —— 可能杀掉的是兄弟的工作**。如实记录为违规。
- M93 归档里的 `evidence/m93_accept_run_*.log` 与 `m93_check_*.run.log` 含**设备耗时行**
  （「中位 X ms」「每次启动 Y us」等），**本来就非逐字节可复现**（M93 自己已注明每次 run
  有 18~24 行差异）。本轮按 M93 的口径只比「那一行 `ALL PASS（checks=…, guards=…, fails=0）`」
  与各 `check_*.py` 的 `RESULT:` 行 —— 这两类读数在逐项比对下相同。**不要把「逐字节相同」的要求

- 重取读数用的中间产物（dump / 镜像 / 副本）都在 `/tmp`，未入仓。

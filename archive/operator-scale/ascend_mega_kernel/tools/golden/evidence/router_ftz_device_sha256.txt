# M46 取证：router FTZ 复现所用设备 dump / 权重 / 上游证据的 sha256

## 为什么需要这份文件
M46 的整改判据是"设备行为是对的、golden 缺 FTZ 建模"——所以本 mission 的对拍必须能回溯到
**具体那批设备 dump**。dump 由 M42 的分支 worktree（`.tower/worktrees/wt-42`，只读使用，本
mission 未改动它）产出；wt-42 未合并、随时可能被改动或回收，故用 sha256 把"那版 m22 kernel +
那批 dump"钉住。本 mission 的重跑命令见 `router_ftz_device_repro.{log,_pre_m46.log}` 文件头。

## 本 mission 独立复现的对应关系（不采信 M42 日志）
`router_ftz_device_repro.log`（M46 修正后 module）与 `router_ftz_device_repro_pre_m46.log`
（M26 合并版 module）是**同一脚本**在两个 module 版本上的原始输出，两张阈值扫描表与 M42 的
`ftz_modeling_scan.txt` 逐项一致（20/0 行；只有 `< 2^-126` 口径给出 0 行）。

| 口径 | 与设备不同（本 mission 实测） | M42 finding 记载 |
|---|---|---|
| 不建模 FTZ（旧） | 125 槽 / **20 行**（权重最大 96 bf16 ulp、32 槽 > 1 ulp） | 20 行 / 125 槽，最大 weight ulp 96 |
| 建模 FTZ（新） | 0 槽 / **0 行**（权重最大 1 ulp） | 0 行，ulp ≤ 1 |

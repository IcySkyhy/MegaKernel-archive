M185 —— B3（m15_attn_fa_core.h）跨核改 mode 2 + P 改走 L1 的**设备读数与定位**
================================================================================
（**后续**：M189 已定位并修复「S/PV 系统性错」的根因 —— `L1 -> L0B` 的生产侧 MTE1
`Acq/Rls` 被放到 `ks`/`nh` 循环之外。本文件的读数与“未定位”结论是 M185 当时的口径，
见 `M189_readings.txt`。下文逐字保留。）
日期：2026-10-05。设备：Ascend950PR / NPU0（`npu-smi info` = OK，No running processes 时进锁）。
构建：`m25_attn_fa_core/build/m25_attn_fa_core`（`cmake --build` rc=0 / 0 error）；
      `m15_layer_loop/build/m15_layer_loop`（`cmake --build` rc=0 / 0 error）。
设备纪律：每档各自 `flock -w 300 /tmp/npu0.lock`、进锁先 `npu-smi`、`timeout` 在锁内。

--------------------------------------------------------------------------------
1. 两条改动（本 mission）
--------------------------------------------------------------------------------
(a) **跨核 mode 4 → mode 2**：`FacCcSet/FacCcWait` 的 `0x4` 改 `0x2`；删掉 `FAC_AIV_CH(=16)`
    那套「AIC 侧对 AIV1 通道 +16」的双通道 set/wait（AIC 侧调用点由 10 → 5）。
    mode 2 配对口径（`docs/05 §2`）：AIC `set` 一次 → 配对 2 个 AIV 各 `wait` 一次；
    **配对 2 个 AIV 都 `set`** 后 AIC 的 `wait` 才放行（严格 2 set ↔ 1 wait）。
(b) **P 改走 L1（不落 GM）**：AIV 用 **UB→L1 硬通道**（`DataCopy(dstL1, srcUb, DataCopyParams)`
    逐列分形 burst）把 P 半块写进 L1P(q) 的 [P,SIN] NZ 槽；AIC 侧删掉 `FacGmToL1Nz(pGM_)`，
    只做 `L1 → L0A`。`pScratch` 形参保留、不再使用。

`m15_layer_resources.h` §4f.2 已同步重写为 **mode 2** 的登记（6 号集合不变、去掉 `+16` 通道；
AIC/AIV 调用点 5/9=14；`FacCcPairOkFor` 改为「每通道 1 AIV 行 + 1 AIC 行」；负向对照随代码入库）。
**断言会咬**：临时把 `CC_S_FREE` 的 AIV 行 `set` 改成 `wait` ⇒ 编译期
`static assertion failed ... B3 的 mode-2 通道配对违规`（rc=2），还原后 rc=0。

3. 数值失败**不在本 mission 的两条改动**（单变量对照）
--------------------------------------------------------------------------------
(1) **P 通路对照**：把 AIV/AIC 的 P 换回 M185 前的 GM 中转（其余一字不改）后重建重跑 m=64，
    `OUT_FNV64=0x9294cefcc027e633`、`out[0,0,:4]` 与走 L1 的版本**逐位相同**
    ⇒ **P 走 L1 vs 走 GM 行为等价**，P 通路不是失败点。
(2) **S 的事实**：临时 dump AIV 收到的 S（fp32 32×128）与它算出的 P（bf16 32×128）到 `pScratch`
    （`m=64, h=0, rowBase=0, tile=0, half=0`）：
      · P 行 0 = `[1, 0, 0, ...]`（**one-hot，掩码正确**）；行 r 的有效列 = `0..r`（causal 正确）。
      · 由**同一 dump 的 S** 按 `exp(scale·(S−rowmax))` 复算 P，逐行**吻合**
        （例：行 1 `P=[0.4238, 1.0]` vs 复算 `[0.4232, 1.0]`）⇒ dump 可信、P 确实由该 S 算出。
      · 但该 S **不等于** host 的 `Q·Kᵀ`（`maxdiff ≈ 43`）。
(3) **PV 的事实**：P 行 0 one-hot ⇒ `out[0]` 应 = `V[0]`；实测 `out[0,0,:4]=[-0.5078,-0.8008,-0.5938,0.5703]`
    ≠ `V[0,0,:4]=[0.8516,-0.6367,-0.8672,-0.6484]`，且**四档完全相同**（ctx 无关）
    ⇒ **PV 的输出也是系统性地错**（不是整行 V、不是 halfswap、不是 16 分形转置）。

⇒ **失败点在 cube 的数据面（Q/K/V 装载 → `Mmad` → `Fixpipe`/dualDst）**，与本 mission 的
   mode 2 / P 通路两处改动**无关**（本档此前一直挂死，这条路径从未被任何数值读数验证过）。
   根因**未定位**；已排除的候选见 `exclusions.md`（14 条）。

4. 复现
--------------------------------------------------------------------------------
```
cd <repo>
source /usr/local/Ascend/ascend-toolkit/set_env.sh
cmake -B m25_attn_fa_core/build -S m25_attn_fa_core -DCMAKE_BUILD_TYPE=Release
cmake --build m25_attn_fa_core/build -j4
mkdir -p m25_attn_fa_core/out
for m in 16 64 96 128; do
  flock -w 300 /tmp/npu0.lock bash -c "
    npu-smi info | sed -n '9,12p'
    M25FA_M=$m timeout 60 ./m25_attn_fa_core/build/m25_attn_fa_core core m25_attn_fa_core/out"
  python3 m25_attn_fa_core/check_ref.py m25_attn_fa_core/out/m${m}_core --quiet
done
```

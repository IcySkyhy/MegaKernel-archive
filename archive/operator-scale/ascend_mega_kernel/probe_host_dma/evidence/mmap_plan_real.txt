== A. 真实几何方案（128 分片 / 2,500,012 行 / 160 列 / 2 B）==
全局行数            : 320,001,536
行宽                : 320 B
表总大小            : 102,400,491,520 B = 102.40 GB = 95.37 GiB
单分片数据段        : 800,003,840 B = 762.9 MiB
每 token 查 16 行   : 5120 B

-- 行 id → 文件位置（跨分片）--
  shard      = id // 2,500,012           # 0..127
  local      = id %  2,500,012           # 分片内行号
  file_off   = data_off[shard] + local*320   # data_off 从该分片 safetensors 头解析（8B 头长 + JSON）

-- 为什么必须 mmap（且不能物化）--
  host cgroup             : 32 GiB（实测 memory.max=34359738368）
  表 / cgroup             : 2.98x  ⇒ 整表**装不进**（差 3.0 倍）
  磁盘可用                : 402 GB ⇒ 整表 102.4 GB 放得下（占 25%）

-- 建议的驻留/窗口策略（依据 probe_host_dma 的实测代价）--
  窗口大小 256 MiB × 4 个 = 1024 MiB 注册内存（约 1.00 GiB，占 cgroup 3.1%）
  依据① 注册代价（从 evidence/logs/regbench*.log 解析，跨独立进程中位+区间）：
         4MB median=48.161ms[n=5,range=6.780..72.969] / 64MB median=576.875ms[n=5,range=309.046..836.124] / 256MB median=6730.705ms[n=5,range=1144.784..10211.197]
        ⇒ 窗口要**一次注册、反复复用**，绝不按次注册
        ⇒ 池启动注册耗时（按上表线性外推，**推算、未端到端实测；且方差极大**）：4×4MiB≈[0.0, 0.3]s(中位0.2s)  4×64MiB≈[1.2, 3.3]s(中位2.3s)  4×256MiB≈[4.6, 40.8]s(中位26.9s)
           ⚠ 方差远大于尺寸效应：注册耗时的跨批次离散可达**一个数量级到数十倍**（见 README §3.6 跨批次表）
             ⇒ **池大小必须在目标机上实测确定**，不要照搬上面的外推值
  依据② 注册本身相对 touch 不额外增常驻（RSS delta=0 kB；逐条见 README §3.5）
        ⇒ 窗口池的常驻成本 ≈ 池大小 1024 MiB；cgroup 32 GiB 下要留足余量
  依据③ device 单侧读带宽约 20–22.5 GB/s（host-mapped，由 evidence/logs/read_run*.log 复核）
        ⇒ 搬 256 MiB 进 staging 约 11.4–12.5 ms 量级（另取决于是否命中 page cache）

-- 必须避免的两条（错误码为稳定契约，非计时类测量）--
  1) 直接注册 file-backed mmap 让设备读：aclrtHostRegisterV2 rc=507899（file/filerd/filepriv 全拒；
     README §3.5 表 + evidence/logs/filemmap_*.log，跨 3 批稳定）
  2) 未注册指针 / 越界让设备读：kernel aclError=507035（README §3.4 + evidence/logs/{unreg,page}_*.log）

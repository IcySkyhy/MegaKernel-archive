# Extending mkc

Four kinds of change come up, and each is meant to touch one place. If you find
yourself editing three files for one of them, that is a bug in the structure and
worth fixing before the feature.

---

## 1. A new model architecture

**Usually: nothing.** The frontend (`mkc/src/arch.rs`) is one generic
decoder-only reader, not a family of per-model readers. It *probes*:

* config keys with fallbacks (`num_key_value_heads` or `num_attention_heads`,
  `head_dim` or `hidden/heads`, four conventions for per-layer sliding windows)
* tensor roles against candidate name lists, so a fused `qkv_proj` and separate
  `q_proj/k_proj/v_proj` are the same thing downstream

Start with `mkc analyze <model_dir>`. It parses, prints the resolved IR and the
bytes-per-token table, and never touches a GPU. If it prints a sensible model,
`mkc build` will very likely work.

If a role does not resolve, `analyze` fails and **names every missing role and
the names it tried**. Add the new name to that role's candidate list in
`arch.rs`. That is the whole change.

If the architecture needs a numerical convention that is not in the IR — a new
norm placement, a different router scoring rule — add a field to `ir.rs`, set it
in `arch.rs`, and read it in the template that needs it. Then add it to
`validate.rs` so models that need it are refused until it is lowered.

**The contract:** mkc either produces a kernel that passes the gate, or it
refuses and says which feature it lacks. Never a third thing. `validate.rs`
exists to keep that true; when you add a field to the IR that the backend does
not lower, add the refusal in the same commit.

## 2. A new weight format

Everything lives in `mkc/src/quant.rs` plus one core in
`runtime/include/mk/gemv.cuh`:

1. **`ir.rs`** — a `Quant` variant, its `bytes(rows, k)` formula, its `tag()`
   (its exact identity, for the loader and the report) and its `core()` (the
   gemv core it runs on, which is the key the machine model is indexed by; two
   spellings of the same core share one calibration).  The planner needs only
   these; it prices every stage from bytes.
2. **`quant.rs::hf_suffixes`** — the checkpoint's tensor-name suffixes, appended
   to a base name with its trailing `.weight` stripped.
3. **`quant.rs::parts`** — the tensors to bind, their stored dtype, and the C
   type of the pointer the kernel reads them through.
4. **`quant.rs::Mat::gemv`** — the call a stage body emits.
5. **`mk/gemv.cuh`** — the core itself, and a case in `calib/calib.cu` that
   records its rates under the same `core()` name.  Without that the planner
   prices it from the dense curve scaled by a ratio, which is a proxy, not a
   measurement -- and a silent one.  Bump `SCHEMA` in `hw.rs` when the shape of
   the tables changes so old machine files are refused instead of quietly
   falling back.
6. **`arch.rs::detect_quant`** — recognise it from `quantization_config`.
7. **`validate.rs`** — add it to the supported list.

Nothing else branches on the format. `layout.rs` and `emit.rs` build the loader and the
`LayerW` struct from `parts`; `codegen.rs` asks a `Mat` for its call.

**Normalise at load time.** AWQ and GPTQ pack int4 along different axes with
different interleavings. Rather than two kernels, the loader repacks both into
one canonical layout. A format's weirdness belongs in the loader's row mapping,
not in the inner loop.

## 3. A new stage

1. A `StageKind` in `plan.rs`, and the code that pushes it into the schedule
   with its item count, bytes, bytes-per-item and shared-memory footprint. The
   cost model prices it from those; no new cost code is needed.
2. A template in `codegen.rs` and its filler.
3. One arm in `codegen.rs::stage_call`.

The megakernel body is generated by walking the planner's stage list, so the
stage appears in the kernel, in the standalone profiling kernels, and in the
per-stage timeline automatically. If the stage does not need a grid barrier
after it, say so with `barrier_after: false` and the schedule shortens.

The shared arena is sized as the maximum of the stages' declared `smem`, so a
stage that declares its footprint cannot overflow it.

**Every barrier must be unconditional.** The host advances the grid barrier's
arrival counter by a compile-time count (`MK_BARRIERS`) per launch, so a kernel
that performs a different number of rendezvous on some path does not produce a
wrong answer -- it hangs. Keep the rendezvous outside every `if`; the sampler
does exactly that, and says so. If you get it wrong the spin gives up after a
second and the runtime tells you which arrival it was waiting for, but do not
rely on that: it is a diagnostic, not a safety net.

## 4. A new GPU

```bash
nvcc -O3 -arch=sm_XX -Iruntime/include -o calib calib/calib.cu
./calib hw/<device>.json
```

`hw/<device>.json` is the entire machine model: SM count, register file, shared
memory, the measured streaming ceiling, the grid barrier's cost by grid size,
and the stage-rate table for every (core, block size, row blocking, reduction
length). The planner reads nothing else about the machine. `mkc` finds the file
from `--hw`, else `$MKC_HW`, else `hw/<device>.json` — the env var is what lets a
batch job calibrate into a writable directory, since `/home` is read-only on
many compute nodes.

The file carries a `schema` and `mkc` **refuses** an older one rather than
silently pricing every stage from a proxy curve, which is what a missing table
looks like from the inside. Bump `hw::SCHEMA` whenever the tables' meaning
changes.

Nothing in the runtime library is Hopper-specific: the MXFP4 decode is `PRMT`
and `__byte_perm`, the grid barrier is an atomic counter and a `volatile` spin,
`%globaltimer` and `__nanosleep` are sm_70+. A new architecture should need a
calibration run and an `-arch` flag, not code.

## Where the invariants live

| invariant | enforced by |
|---|---|
| the compiler refuses what it cannot lower | `validate.rs`, called before planning |
| the generated kernel is arithmetically right | `runtime/include/mk` + `tests/test_prims.cu` |
| the generated *schedule* is right | the gate in `harness/mkrun.py` |
| the schedule is not cheating | `harness/mkguard.py` |
| a stage cannot overflow the arena | `plan.rs`: arena = max(stage.smem) |
| the plan's occupancy is reachable | `search.rs`: every occupancy is compiled and only what ptxas places is kept |
| the fastest of those is chosen | `--verify`: each survivor is timed on the machine |
| a benchmark row cannot be stale | `zoo.sh` deletes `result.json` before the run and says so if it is not recreated |
| the README's numbers are the measured ones | `scripts/table.py` rewrites the table from the TSV; nothing is transcribed |
| compilation is a pure function | `tests/run_tests.sh` compiles the same model twice and diffs the trees |
| a header edit rebuilds the kernel | generated `Makefile` lists `mk/*.cuh` |

## Running the tests

```bash
tests/run_tests.sh     # primitives, every model compiles, unsupported refused
python harness/run.py <out> --model <dir> --guard    # gate + guard on real weights
```
